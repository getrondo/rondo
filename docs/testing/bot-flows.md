# Bot flows

One row per flow. `Test` names the test that proves it; `flow-matrix.test.ts` fails when a row that is not planned has no
test of exactly that name. Layer: `update` runs Telegram updates through `handleUpdate` with the recorded Telegram API and
PGlite, `service` calls the domain service, `cron` runs the maintenance job or the hourly teams check, `postgres` runs on a
real Postgres, `unit` a pure function.

Only a real test group can prove what the recorder cannot: that Telegram accepts the poll description and route button,
that a forwarded poll keeps its description, route button and votes, that stopPoll on the original closes the forwarded
copies, pinning rights, delivery of chat member updates, and that votes on a copy forwarded by an admin to a group
without the bot still arrive as poll answers with public voters. For teams: that text mentions by Telegram ID survive a forward and
open the profile, and whether editing a posted line-up notifies the mentioned players again.
